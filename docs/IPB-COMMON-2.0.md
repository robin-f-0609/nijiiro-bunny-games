# 参加型デジタル絵本・制作共通仕様書

文書ID：IPB-COMMON  
版：2.0  
作成日：2026年9月23日  
改訂日：2026年9月23日  
用途：企画・脚本・演出・実装を担当する人およびAIへの共通指示  
位置づけ：にじいろばにーの作品制作を起点にした、題材や登場人物を限定しない制作基準

## 1．目的と使い方

本書は、作品が変わり、制作を担当する人やAIが変わっても、参加型デジタル絵本として大切にする体験と品質を引き継ぐための共通仕様である。過去の会話を知らない担当者も、本書と今回の作品情報を読めば制作を進められることを目指す。

再現する対象は「子どもが物語に関わる体験を設計する方法」である。特定の登場人物、世界観、筋書き、二択の数、画面数、感動的な結末などを全作品に繰り返す必要はない。

使用時は次の順で進める。

1. 本書全体を読み、今回依頼された作業の範囲を確認する。
2. 今回の作品情報・既存作品の資料・作者の指示を確認する。
3. 確定している内容と、今回提案する内容を区別する。
4. 本書の制作手順に沿って、依頼された段階まで制作する。
5. 完成基準に照らして点検し、成果物と未解決事項を引き渡す。

本書だけでは、新しい作品の登場人物や物語は確定しない。新作依頼の内容から補える項目は仮案として進める。既存設定との矛盾や作品の根幹に関わる不明点だけを、必要に応じて作者に確認する。

本書は一つの共通仕様書であり、特定作品の完成シナリオと実装コードは含まない。画面ごとに引き継ぐ項目と、今回の作品への適用例を含む。

**制作の中心は「文章を読み、想像し、ときどき参加しながら、一冊のお話を進める体験」である。文章と余白だけの画面を完成形として認め、必要な場面に絵・音・操作を配置する。**

2.0では、実際のプロトタイプ動画2本、既存素材の確認、作者による「テキストベース」「人物の実物を出さず想像で埋める」という指示を反映した。動画で確認した現状と、今後の制作で採用する標準を区別する。

## 2．作品の定義と目指す体験

### 2.1 定義

参加型デジタル絵本とは、スマートフォンなどで物語を読み進めながら、登場人物への働きかけ、選択、発見、創作などを通して、読者が物語に関われる作品である。

基本の利用場面は「大人が読み、子どもが参加する」「子ども自身が読み、操作する」の二つ。作品ごとに対象年齢や読み方の比重を調整する。大人が音読する読み聞かせと、収録音声による自動読み上げは別の機能として扱う。

ページを送る操作に加え、読者の働きかけに物語が応える場面を設ける。反応は大きな分岐でなくてもよい。人物の返事、表情、絵や音の変化、小さな発見などでも成立する。

### 2.2 表現の基本形

基本は、スマートフォンの縦画面で一画面ずつ読む形式とする。紙面に文章を置き、必要な小物・挿し絵・選択肢を加える。場面が変わるたびに全面背景を切り替えることや、登場人物を常時表示することは要求しない。

- 場所、人物の姿、動き、表情は文章で伝えてよい。
- 登場人物の画像がないことを素材不足と判定しない。
- 読む画面、触る画面、絵を眺める画面を使い分ける。
- 絵を出す判断は、その絵が読者の理解・発見・感動・操作に何を加えるかで行う。
- スマートフォンの画面を装飾で埋めず、音読の間や想像のための余白を残す。
- 通常は文章が中心。虹を初めて見る瞬間などでは、一時的に絵だけを主役にしてよい。

文章中心という方針は、全画面から画像をなくすことや、すべての作品の画風を同一にすることを意味しない。

### 2.3 目指す体験

- 登場人物の望みや困りごとがわかり、関わってみたくなる。
- 自分がしたことに物語が反応し、参加した手応えがある。
- 親子で声を出す、笑う、相談する、黙って眺める余地がある。
- 子どもが自分のペースと参加方法で楽しめる。
- 読み終えたとき、一つのお話を味わった満足感や余韻がある。

これらは制作上の目標であり、学習効果や発達上の効果を保証するものではない。教育的な題材でも、登場人物や出来事の魅力、遊ぶ楽しさを具体的に設計する。

### 2.4 作品の位置づけ

| 種類 | 主な役割 | 設計時の確認 |
| --- | --- | --- |
| プロローグ | 人物や世界に親しみ、本編への期待をつくる | 本編の驚きや謎をどこまで見せるか |
| エピローグ | 本編の続きを味わい、体験を持ち帰る | 本編の達成や余韻をどう受け継ぐか |
| 番外編 | 別の人物や出来事を楽しむ | 本編について必要な前提は何か |
| 独立作品 | 単体で物語と参加を楽しむ | 作品内だけで状況と目的が伝わるか |

公演連動作品でも、デジタル絵本を遊んでいない観客が本公演を楽しめる構成を基本とする。本編の知識が必要な作品には、その前提を短く示す。

## 3．要求の強さと、変更できる範囲

本書の「必須」は適合に必要な条件、「基本」は事情に応じて変更できる標準、「任意」は作品に合う場合だけ使う要素を表す。

今回の作者の明示的な指示は、本書の一般的な方針より優先する。作者の意図に沿う変更は、その理由を作品の制作記録に残す。本書に書かれた例を、そのまま作者の確定設定として扱わない。

| 区分 | 内容 |
| --- | --- |
| 必須 | 設定と展開の整合、読者の役割がわかること、参加に対する認識可能な反応、場面と分岐の接続、確定と提案の区別 |
| 基本 | 文章と余白を中心にする、読者が進行速度を決める、音なしでも進める、操作の苦手さで行き詰まらない、親子読みと一人読みへの配慮 |
| 任意 | 複数の結末、収集要素、読み上げ音声、歌、途中保存、読者への直接の呼びかけ、本や案内役を使った枠物語 |

作品ごとに決めるものは、対象年齢、利用場面、長さ、登場人物、世界観、テーマ、読者の役割、操作の種類、分岐数、画面数、絵・音の表現である。共通仕様で一律に固定しない。

## 4．設定・作者の意図・情報の扱い

### 4.1 情報の区分

| 区分 | 意味 | 制作時の扱い |
| --- | --- | --- |
| 確定設定 | 作者が定めた人物・世界・出来事の事実 | 新しい案を合わせる基準にする |
| 採用済み | 今回の作品で作者が採用した内容 | 改訂時も変更点を明示して引き継ぐ |
| 提案 | AIや担当者が追加した未採用の内容 | 確定設定と混ぜず、提案だとわかるようにする |
| 未設定 | まだ決めていない事項 | 必要なら仮案を置き、仮定を明記する |
| 残す謎 | 答えを明かさないと決めた事項 | 正体や理由を勝手に確定・説明しない |

過去にAIが書いたという理由だけで、設定を採用済みにしない。「未設定」と「残す謎」は区別する。人物が知っていることと読者が知っていることも区別する。

既存資料を使う場合は、資料名と版を記録する。矛盾した資料がある場合は、今回の作者の指示と明示された最新版を確認し、解消できない根幹の矛盾を勝手に埋めない。

### 4.2 本編との接続

公演や別作品と連動する場合は、以下を設計時に明らかにする。

- 時系列上の位置と、接続する出来事。
- 共通する人物、物、小道具、歌、台詞など。
- 今回明かす情報、本編で初めて明かす情報、引き続き残す謎。
- 本編を知る読者への楽しみと、知らない読者に必要な説明。

本編に出る詩や歌を使う場合は、作者が定めた言葉を尊重する。言葉が生まれる場面を描くなら、それを見た・感じた・書きたくなった理由が伝わるようにする。

## 5．物語の設計

### 5.1 最初に決めること

次の問いに、短く具体的に答えられる状態にする。

1. 誰のお話で、その人物は今、何をしたいのか。
2. 何に困る、何を知らない、何が気になっているのか。
3. 読者は誰として、何に関わるのか。
4. 何が起きれば、この一話を読み終えた満足につながるのか。

大事件や悪役は必須ではない。発見、待ち合わせ、準備、小さなすれ違いなども物語の中心になる。人物の成長を必ず起こす必要もない。

### 5.2 人物の変化を描く場合

「最初の状態」「変化を促す出来事」「後半の行動」を対応させる。性格の説明だけで、描写したことにはしない。

例えば、慎重な人物が自分から踏み出す話なら、冒頭で許可を確かめる、決まりを読み返す、足を止めるなどの行動を見せる。後半では同じような状況で違う行動を選ぶことで、変化を伝える。

人物を動かす出来事を飛ばし、最後だけ立派な台詞を言わせない。読者の関わりが変化に影響する設計も有効だが、すべての変化を読者のおかげにする必要はない。

### 5.3 感情と余韻

楽しさ、怖さ、寂しさ、迷いなどが同時に存在してよい。感情そのものを正誤判定したり、登場人物が悲しむたびに明るくなる選択を要求したりしない。

笑い、静かな観察、相談、操作を作品に合う配分で組み合わせる。結末では、その話で始めた問いや出来事に一定の区切りをつける。続編への余白と、今回の未解決な手順を混同しない。

## 6．参加とインタラクションの設計

### 6.1 基本のつながり

各インタラクションは、次の四段階で説明できることを必須とする。

**出来事 → 読者が関わる理由 → 操作・参加 → 物語の反応**

例：人物がくしゃみをして紙を散らす → 拾うのを手伝いたい → 紙をタップする → 紙が集まり、人物がお礼を言ってお話が進む。

この例で重要なのは因果関係であり、くしゃみや紙拾いを他の作品にも必ず入れることではない。

### 6.2 参加の種類

| 種類 | 例 | 読者に返るもの |
| --- | --- | --- |
| 手伝う | 拾う、運ぶ、そろえる | 状況が改善し、人物が反応する |
| 教える | 名前や場所を伝える | 人物の理解や行動が変わる |
| 選ぶ | 道、言葉、行動を選ぶ | 台詞、景色、出来事などに違いが出る |
| つくる | 絵、音、名前を加える | 自分が加えたものを確かめられる |
| 気づく | 絵や言葉から発見する | 隠れていたものや意味が見える |
| 見守る | 待つ、一緒に眺める | 人物の行動や景色を味わえる |

見守る場面だけに選択ボタンを無理に足す必要はない。作品全体の中で、能動的に関わる場面と受け取る場面を構成する。

### 6.3 選択と失敗

- 選ぶ前に、何を選んでいるかが子どもに伝わる表現にする。
- 選択後は、選んだことへの反応を示す。大筋が同じ場所に合流してもよい。
- 展開が変わらない選択でも、返事や絵などに意味のある違いをつくる。
- うまくいかない選択、勘違い、おかしな結果を使ってよい。笑いや発見、再挑戦につながるようにする。
- 間違えた子どもの人格や能力を責める台詞を、システムの評価として使わない。
- 気持ちや好みを尋ねる選択には、作品が望む「正しい気持ち」を隠して設定しない。
- 知識を教える場面は、答えを知らなくても人物とのやり取りで理解し、進められるようにする。

「全選択が成功する」「必ず複数の結末をつくる」は共通要件ではない。分岐の規模は、その作品の楽しさと制作条件に合わせる。

### 6.4 選択の型を区別する

各選択場面で、次のどの型を使うかを明示する。作品全体を一つの型に揃える必要はない。

| 型 | 進み方 | 使う目的 | 設計上の条件 |
| --- | --- | --- | --- |
| 表現・好み型 | どれを選んでも、固有の反応を経て先へ進む | 本に描くもの、言葉、好きな音などを選ぶ | 正解・不正解を設けない。選んだ内容を後半で再表示する場合は記録する |
| 発見・訂正型 | 呼び名や見立てに人物が反応し、後で新しい知識に出会う | 知らないものを知る楽しさ | 初めの選択を否定するだけで終わらせず、勘違いも思い出として残せる |
| 試行・再挑戦型 | 試す→結果を見る→その場で別の手を選ぶ→合流 | 人物を動かす言葉や方法を試す | うまくいかない結果にも会話・発見・笑いを用意し、進める経路を残す |
| 経路分岐型 | 選択で行く場所や出来事が変わる | 異なる道を楽しむ | 分岐先、合流条件、持ち物、結末への影響を記述する |

### 6.5 試行・再挑戦型の標準

基本の流れは「選ぶ → 対象の変化 → 人物の反応 → 次の試みへの案内 → 同じ場面で再選択 → 本筋へ合流」とする。

プロトタイプの例では、スイッチを「ぜったいに押せ」に書き換えると人物が疑って押さず、ウサコが「別の言葉で、もう一回！」と促す。選択画面へ戻ると試した選択肢が消え、「押すと、きゅうりがあるかも」が残る。後者を選ぶと人物が押し、物語が進む。

ここから引き継ぐのは、選んだ結果が会話として返ること、試行を覚えること、その場から続けられること。スイッチやきゅうりの設定を他作品の必須要素にしない。

- 一度試した手を除外する方式を使う場合は、選択肢の非表示／無効化のどちらかを作品側に記す。標準例は非表示。
- 再挑戦する同じ場面では、試した手の履歴を保つ。
- 残り一つになっても、自動で選択を確定しない。読者が押して進める。
- 選択肢がゼロになる設計にしない。必要ならヒント、案内役の手助け、共通の進行手段を用意する。
- 基本は減点、残機、ゲームオーバー、物語冒頭からのやり直しを伴わない。
- 笑いは人物同士のすれ違いや予想外の結果から生む。読者を「だめ」「頭が悪い」と評価しない。
- 文言を変えても人物が必ず従うとは限らない。人物の性格と反応の因果関係を守る。

作品側で「誤答なし」と決めた表現・好み型へ、この再挑戦方式を機械的に導入しない。特に感情・好み・創作の選択に、隠れた正解を設けない。

### 6.6 分岐と記憶

後半へ影響する選択は、何を覚えるかを明記する。選ばなかった道で手に入る物や、まだ出会っていない人物が、後半に無条件で登場しないようにする。

合流する場面では、どの経路でも台詞と状況が成立することを確認する。再選択や「もどる」で、持ち物、選択済みの絵、訪問済みの場所などをどう扱うかも決める。

状態の標準は次のとおり。保存機能を実装しない場合でも、一回の読書中の状態は管理する。

| 操作・出来事 | 状態の扱い |
| --- | --- |
| 通常のページ送り | 選択・持ち物・操作完了を引き継ぐ |
| 同じ選択場面への再挑戦 | 試行履歴を保持し、指定された選択肢を除外する |
| 「もどる」で読み直す | まずは以前の選択・結果を保持。戻っただけでは結果を取り消さない |
| 過去の選択を明示的に変更する | その選択に依存する後続結果を取り消し、新しい経路に沿って再計算する。無関係な前段の履歴は保つ |
| 再挑戦場面そのものをやり直す | 明示された場面リセット操作がある場合だけ、その場面の試行履歴を消す |
| 「もういちど よむ」 | 今回の物語の選択、試行、操作完了、メーター等を初期化する |
| 再読み込み・再訪問 | 保存なしなら最初から。保存ありなら版と保存位置を確かめて再開する。作品仕様に明記する |

同じページの再表示・連打で、紙が二重に集まる、燃料が余分に増える、音が重なり続ける状態を作らない。メーターなどは場面と選択の状態から表示を決め、表示のたびに無条件で加算しない。

## 7．読み聞かせとスマートフォンでの体験

### 7.1 文章と画面

- 基本は1画面＝一つの読書ページ。通常の縦持ち・標準文字サイズでは、本文・必要な絵・操作が一画面に収まる構成を目指す。
- 本文は90〜120字程度を最初の目安にする。下限でも厳密な上限でもない。話者名・句読点を含む表示本文で数え、制作指示やボタン文言は本文字数から分ける。ただしボタンも画面内の場所を使うものとして設計する。
- 本文量は、実際の文字サイズ、改行、行間、画像の大きさ、選択肢の数を合わせて判断する。「字数以内だから収まる」と判定しない。
- 画面が足りない場合は、まず重複説明や画面の区切り、挿し絵の大きさを調整する。文章を極端に小さくして詰め込まない。
- 白い画面の一文、選択、静かな観察、ページを一枚ずつめくる操作、決まりの復唱、最後の一文などは、意図して短い画面にできる。
- 台詞は話者がわかる名前や表示を付ける。色分けは補助であり、色だけに依存しない。
- ふりがな、ひらがな、語彙は対象年齢に合わせる。ひらがなだけで読みにくい場合は分かち書きなどを使う。
- 読者向け本文と制作指示を分離する。本文や詩、選択肢を画像に焼き込まず、修正・拡大可能な文字として扱うことを基本とする。
- ブラウザの上下の操作欄を含めた実際の表示領域で確認する。文字拡大や横向き、小さな端末ではスクロール等で読める逃げ道を設け、画面外を切り捨てない。

紙の色、余白、行間、本文の色、ボタン位置は作品内で統一する。プロトタイプのクリーム色の紙面は採用できる見本であり、すべての作品に同じ色を強制するものではない。

### 7.2 進行・表示・操作

基本は読者が進める。音読中に本文が消えたり、ページが自動で進んだりしないようにする。段落が順番に現れる演出と、ページが自動で切り替わる動作を区別する。

以下は2.0で定める標準であり、既存プロトタイプの全挙動を動画で確認できたという意味ではない。

| 画面の状態 | 読書領域のタップ | 選択・操作ボタン |
| --- | --- | --- |
| 本文が段階的に表示されている | 同じ画面の本文を最後まで表示する。次のページへは進めない | 本文の表示完了後に有効化することを基本とする |
| 本文の表示が完了した通常ページ | 次のページへ進む。「つぎへ」でも同じ動作 | 戻る・音などはそのボタンの機能だけを実行 |
| 選択を待っているページ | ページを進めない | 選んだ選択肢の反応へ一度だけ進む |
| 紙拾いなどの操作ページ | 遊びのない領域では進めない | 対象への反応のみ。代替ボタンも同じ完了状態につなぐ |
| 任意探索のページ | 誤操作防止のため、明示された「つぎへ」で進む | タップを楽しめる。「つぎへ」は初めから使える設計も可 |
| 操作完了・反応表示中 | 表示途中なら全文表示に留める | 反応を見せてから「つぎへ」を使える状態にする |
| 静かに絵を眺めるページ | 作品で定めた手動操作で進む | 短い最低待ち時間を置く場合は理由を記す。長い強制待機にしない |

本文の段階表示は、一文字ずつに限定しない。台詞・文・段落のまとまりで穏やかに現れる方式を基本とし、段落ごとの順序と間を指定できるようにする。表示完了後は文章を残す。全文を一度に表示する設定や、動きを減らす環境でも情報が失われないようにする。

一回のタップで「全文表示」と「次ページ」を続けて実行しない。選択ボタンのタップが、背後のページ送りにも伝わらないようにする。切り替え時の連打で、未読ページや選択を飛ばさない。

- 「つぎへ」「もどる」の役割と配置を一貫させる。「もどる」は読み直しのために使え、状態の扱いは6.6に従う。
- 指で押しやすい大きさと間隔にし、絵の細い輪郭を正確に押すことを要求しない。
- ドラッグ、両端への同時タッチ、連打などを使う場合は、単一のボタンでも同じ結果に到達できるようにする。
- 紙拾いは三枚戻ったら反応を示し、読者が次へ進む。完了直後に本文を自動で消さない。
- 読む速度や操作の遅さで失敗させない。物語の緊迫感を、現実の時間切れへ自動的に変換しない。

### 7.3 音・発話・身体参加

- 音楽、効果音、収録された語り、大人による音読を別々に設計する。
- 音のオン・オフを選べ、音が出ない場合も必要な情報が伝わることを基本とする。
- 声を出す、手をたたく、体を動かす誘いは、できる範囲で参加できる表現にする。
- 「できた」「きいている」などで進められる方法を用意し、マイクによる判定を標準の前提にしない。
- 音声を認識していない作品で、実際の発話内容を聞き取ったと誤認させる応答をしない。
- 動きや音の演出が終わるまで、長時間操作を受け付けない構成を避ける。作品に必要な待ち時間は長さと理由を定める。

作品の本文に、データ形式、実装用の変数名、制作管理上の注意などを表示しない。

歌の専用ページを設ける場合も、読者が手動で続きへ進める。再生終了や次ページで音を止める／継続するかを作品側で指定する。音量や音の有無が進行条件にならないようにする。

### 7.4 絵・素材・動きの使い方

素材を発注・生成する前に、次の優先順で表現方法を検討する。

1. 文章と余白で伝える。
2. 既存の小物や挿し絵を使う。
3. 配置・拡縮・色・簡単な図形・文字の変化で表現する。
4. 場面の理解や操作に必要な画像だけを新しく作る。

| 表現したいもの | 基本の扱い |
| --- | --- |
| 人物の姿・表情・動作 | 文章で成立させてよい。人物ごとの立ち絵や表情差分を自動的に制作対象へ加えない |
| 海・森・虹などの風景 | 初めて見る瞬間、記録の絵、回想など、意味のある箇所で挿し絵として使う |
| 紙・本・にんじんなど | 触る対象や物語の手がかりとして小さく表示できる |
| メーター・雨粒・ページの開閉 | 単純な図形やコードによる動きでもよい。すべてを動画素材にしない |
| 装飾のウサギや星 | 任意。本文・選択肢に重ならず、静かな場面では減らすか止める |
| 白いページ | 何も描かない状態自体を表現として尊重する |

画面数と画像数を連動させない。同じ絵を、拾う紙、旅の記録、後半にめくるページへ再利用できる。変更がある絵はその変化を保つ。雨でにじんだ文字が後半で無断で元へ戻るなどの不整合を作らない。

素材台帳には、素材ID、出典、確認済みの寸法・透過の有無、用途、使用画面、必要な加工、採用状況を記す。ファイル名だけで内容を推測せず、画像を見て判断する。JPEGの単色背景を透過済みと扱わない。

既存キャラクターの画像が見つかっても、別の登場人物へ勝手に割り当てない。顔を見せない人物に、既存の正面画を使わない。素材不足を理由に物語の謎や設定を変更しない。

### 7.5 最低限の代替体験

- 音が出ないとき：必要な情報を文字、絵、メーター等で示す。
- 細かく触れないとき：「いっしょにひろう」「ひろげる」などで同じ結果に進める。
- 動きを減らすとき：飛ぶ・揺れる・開く演出を静止した結果表示へ置き換えられる。
- 画像の読み込みが失敗したとき：本文・対象名・代替操作を残し、進行不能にしない。意味に必要な画像には説明を用意し、装飾は読み上げを妨げない。
- 音読を中断したとき：次へ進めるまで本文は残る。音や演出の終了だけで勝手に先へ進まない。

## 8．作品ごとに確認する情報

以下は制作の入力項目であり、すべてを作者への質問にするという意味ではない。資料と依頼内容からわかる情報を先に整理する。十分な情報があれば、そのまま制作を進める。

| 項目 | 必要な内容 |
| --- | --- |
| 今回の作業 | 企画、あらすじ、脚本、改稿、実装、公開などの依頼範囲 |
| 作品の位置づけ | プロローグ、エピローグ、番外編、独立作品など |
| 読者と利用場面 | 対象年齢、親子読み・一人読み、公演前後や家庭など |
| 目指す楽しさ | 笑い、発見、冒険、親しみ、余韻などの具体的な体験 |
| 人物と世界 | 性格、望み、関係、話し方、世界で可能なこと |
| 既存作品との関係 | 参照する資料と版、時系列、残す謎、使用する言葉 |
| 読者の役割 | 誰として、誰に、どのように関わるか |
| 結末の方向 | 今回区切りをつける出来事と、残す余白 |
| 表現と制作条件 | 長さの目安、絵、音、使用できる素材、端末など |
| 今回の固定事項 | 作者が変えたくない要素と、提案してよい範囲 |

長さ・分岐数・画面数などの可逆的な判断は、根拠を付けた仮案として進められる。対象年齢が未定なら、その影響を示し、作品に合う仮の対象を明記する。正体、関係性、本編の結末などを変える案は、採用済みとして扱わない。

## 9．成果物を引き継げる形にする

### 9.1 企画・あらすじの段階

人物の望み、読者の役割、主要な出来事、参加の仕組み、結末の方向がわかる内容にする。採用する世界設定や、今回だけ追加した仮定を識別できるようにする。

### 9.2 シナリオの段階

各場面は、後から別の人やAIが演出・実装できる粒度で記述する。次の情報を明示する。不要な項目には「なし」または「該当なし」を記す。

| 情報 | 記述すること |
| --- | --- |
| 場面IDと場面名 | 他の場面から一意に参照できる識別名 |
| 開始時の状況 | 場所、時間、登場人物、必要な前提 |
| 読者向け本文 | 語りと台詞の実際の文章。話者も明記 |
| 絵と演出 | 見せたいもの、動き、間、音の役割。「画像なし・本文のみ」も明記できる |
| 参加の理由 | 今、何が起き、読者に何をしてほしいか |
| 操作や選択 | 画面に出す言葉、触る対象、進める条件、選択の型 |
| 反応 | 各選択・操作の後に出る台詞や演出 |
| 引き継ぐ情報 | 選択、試行済みの手、持ち物、描いたもの、操作完了など。影響がなければ「なし」 |
| 接続先 | どの条件で、次のどの場面に進むか |
| 代替手段 | 音なしや操作しにくい場合の進め方 |
| 本文の表示 | 一括／段階表示、まとまりの順序、表示途中のタップ |
| 素材 | 素材ID、配置、表示条件。文字だけなら「なし」 |
| 再訪問 | 戻った時の表示、再選択・再操作の可否と状態の扱い |

「選んだ内容に応じていい感じに変わる」のように、重要な反応を後の担当者へ丸投げしない。シナリオ完成時には、全選択肢の反応と接続先を書き切る。本文の言葉と制作指示を混ぜない。

### 9.3 実装へ進む段階

プログラミング言語や仕組みは、作品を動かす環境に合わせる。本書は特定のAI、サービス、ホスティング先、ライブラリを前提にしない。

実装時は、物語の文章・絵・音・分岐と、共通のページ送りや音量操作などを区別し、作品追加や修正の影響範囲を把握できる構成を基本とする。具体的なファイル構成を、脚本段階で固定する必要はない。

共通の実装機能は、ページ表示、段階表示と全文表示、手動ページ送り、選択と反応、試行履歴、分岐の合流、戻る・再読、音の切替、代替操作を中心にする。作品にない機能は追加しない。本文と素材の対応をIDで管理し、ページ番号を変えた場合も接続先を点検する。

ログイン、マイク・カメラ入力、得点ランキング、通知、収集図鑑、全面的なキャラクターアニメーションなどは、今回の作者が求めていなければ標準機能に加えない。

保存する情報がある場合は、何を、どこに、いつまで保存するかと、再開・最初から読むときの扱いを定める。「もどる」による選択変更も含め、状態の変化を確認する。

複数作品を公開する場合は、作品ごとの入口と一覧への戻り方を用意する。印刷物のQRコードに使うURLは継続利用を想定し、変更する場合は既存の入口からの到達方法を設計する。作品一覧の更新と、利用者への通知は別の機能として扱う。

企画やシナリオ作成の依頼から、公開サイトの変更まで自動的に作業範囲を広げない。今回依頼された段階の成果物を完成させる。

## 10．制作手順

以下は担当者の作業手順である。各段階で必ず作者の確認を求める手続きではない。すでにある指示や判断を引き継ぎ、必要な制作を進める。

| 手順 | 行うこと | 次へ進むための確認 |
| --- | --- | --- |
| 1．前提整理 | 入力資料、確定設定、提案範囲、今回の作業を整理する | 不明点と仮定が区別されている |
| 2．体験の中心 | 人物の望み、読者の役割、一話の区切りを決める | 何を楽しむ作品かを短く説明できる |
| 3．あらすじ | 始まりから結末まで出来事をつなぐ | 重要な行動や変化に原因がある |
| 4．場面と参加 | 各場面に参加の四段階を対応させる | 操作する理由と反応が成立している |
| 5．本文と分岐 | 台詞、必要な絵、操作、各反応、接続先、再挑戦を記す | 全経路が最後まで記述されている |
| 6．読み直し | 人物、設定、読者の理解、音読の間を確認する | 説明不足や重複、急な変化を直している |
| 7．経路点検 | 違う選択を通り、持ち物や台詞の整合を確認する | 未選択の出来事への依存が残っていない |
| 8．引き渡し | 成果物の版、実施した確認、未解決事項を示す | 次の担当者が完成範囲を判断できる |

既存の脚本を改稿する場合は、変更対象と関連する場面を中心に直す。作者が評価・採用した要素まで理由なく作り替えない。変更が波及する分岐や後半の台詞は一緒に更新する。

## 11．完成の判断基準

### 11.1 シナリオで点検すること

「適合」「要修正」「該当なし」「未確認」で記録する。「該当なし」には簡単な理由を付ける。自己点検だけで、実際の子どもに伝わったと断定しない。

| ID | 観点 | 確認する証拠 |
| --- | --- | --- |
| C01 | 作品の目的 | 人物の望み、読者の役割、一話の区切りを説明できる |
| C02 | 設定の整合 | 確定設定と矛盾せず、提案を確定扱いしていない |
| C03 | 情報の出し方 | 本編との時系列・公開する情報・残す謎が守られている |
| C04 | 人物描写 | 性格や変化を支える台詞・行動が実際の場面にある |
| C05 | 出来事のつながり | 困りごと、行動、解決や結末の間に必要な原因がある |
| C06 | 参加の必然性 | 各操作を「出来事・理由・参加・反応」で説明できる |
| C07 | 選択への応答 | 各選択の反応が書かれ、何が起きたか読者に伝わる |
| C08 | 経路の整合 | 全選択肢に接続先があり、必要な持ち物や前提が一致する |
| C09 | 再選択 | 戻る、やり直す場合の物語上の扱いが明確になっている |
| C10 | 読みやすさ | 想定年齢で理解する語彙、話者、画面の分け方を検討している |
| C11 | 参加方法の幅 | 音なし・発話なし・細かな操作が難しい場合の進行を設計している |
| C12 | 感情の扱い | 好みや感情を不必要に正誤判定せず、失敗後にも進む道がある |
| C13 | 読後の区切り | 今回の物語が終わったとわかり、残す余白と区別されている |
| C14 | 引き継ぎ | 版、前提、本文、制作指示、未解決事項が区別されている |
| C15 | 文章中心の表現 | 文章だけの画面が許容され、画像は役割と使用箇所を説明できる |
| C16 | 選択の型 | 表現・好み型、発見・訂正型、再挑戦型等が区別されている |
| C17 | 再挑戦の成立 | 試行後の反応、履歴、再選択、選択肢が尽きない経路が定義されている |
| C18 | 表示と進行の分離 | 段階表示、全文表示、次ページ、操作の反応が混同されていない |
| C19 | 状態の再現 | 戻る・選び直す・再読で、後半の内容やメーターが整合する |
| C20 | 素材の適合 | 既存素材を確認し、人物の謎や設定を素材に合わせて変更していない |

必須条件に関わる「要修正」が残るものは、完成シナリオとして扱わない。作者が意図して基本方針を変えた項目は、その意図と代わりの体験を記録する。

### 11.2 実装後に確認すること

文章上の設計確認と、実際に動く作品の確認を分ける。シナリオだけの段階で、以下を動作確認済みと記録しない。

- 想定するスマートフォンの画面で、文字・選択肢・絵が読めること。
- 作品の開始画面から終了まで進め、全分岐の表示と接続が設計どおりであること。表紙を置かない作品も同様に確認する。
- 音のオン・オフ、音が出ない状態でも進めること。
- 代替操作、戻る、再選択、最初から読む動作が成立すること。
- 選んだ絵や持ち物などが、後半でも正しく反映されること。
- 演出中の連続操作や読み込みによって、進行不能にならないこと。
- 親が音読したとき、本文の表示や進行が読み手を急かさないこと。

以下は特に確認すべき具体的な操作例である。採用していない機能は「該当なし」とする。

| ID | 操作 | 期待される結果 |
| --- | --- | --- |
| T01 | 本文の表示途中に一度タップする | そのページの全文が出る。次ページへは進まない |
| T02 | 選択肢を一度押す／素早く二度押す | 結果が一度だけ確定し、反応画面を飛ばさない |
| T03 | うまくいかない手を選び、再挑戦する | 専用の反応を経て戻り、履歴に応じた選択肢が出る |
| T04 | 再挑戦を繰り返す | 選択肢がゼロにならず、最後まで進める |
| T05 | 過去へ戻り、以前と異なる選択を確定する | 後半の台詞・絵・必要な状態が新しい選択に一致する |
| T06 | 紙拾いやメーターの画面へ戻って再表示する | 同じ操作を無条件に二重計上しない |
| T07 | 音を消して森・雨・電話の場面を読む | 必要な情報が文字や見た目でわかり、先へ進める |
| T08 | 代替ボタンだけで操作する | 通常操作と同じ物語上の結果になる |
| T09 | 文字を拡大する／小さな画面で開く | 本文やボタンが切り捨てられず、読んで操作できる |
| T10 | 演出を減らす／画像や音の読み込みが失敗する | 内容と操作手段が残り、進行不能にならない |
| T11 | 「もういちど よむ」を選ぶ | その物語の選択・試行・完了状態が初期化される |
| T12 | 表示完了後、音読のため操作せず待つ | 本文が残り、自動で次のページへ進まない |

可能な段階で、想定読者による試読・試遊を行う。観察するのは、状況や操作が伝わるか、どこで迷うか、反応に気づくか、読み手が急かされないかなど。推定の読了時間は試読結果と区別する。

### 11.3 避けたい不整合の例

| 不整合 | 修正の方向 |
| --- | --- |
| 紙を拾う操作があるが、拾う必要が生じていない | 紙が散る出来事と困っている人物を先に描く |
| 「慎重な人物が変わった」と結末だけで説明する | 冒頭の行動と、後半の違う行動を対応させる |
| 詩や歌が出るが、人物が表現したくなる理由がない | 景色や出来事と、言葉が生まれる瞬間をつなぐ |
| 森へ行かなかった読者にも、森で拾った物が出る | 経路に応じて表示を変えるか、共通で入手する場面を設ける |
| 二択を提示するが、反応も表示もまったく同じ | 選択に応える反応をつくるか、選択自体を整理する |
| 音声が聞こえないと次の操作がわからない | 同じ情報を絵や文章でも伝える |

## 12．AI間の引き継ぎと版管理

成果物は、固有のアプリ機能がなくても読める文章と表を基本にする。Markdownなどのテキスト形式を使える。シナリオからコードを生成するためのデータ形式は、実装環境が決まってから定める。

新しい担当者へ渡す情報は、今回使う本書の版、作品の最新版、確定設定の出典、採用済みの判断、未解決事項である。前のAIの会話履歴がなければ理解できない参照や、存在を確認していない資料名・リンクを残さない。

作品の成果物には、参照した共通仕様の版と作品自身の版を記録する。仕様の改訂と作品の改稿は別に管理する。作品だけの事情を共通仕様に取り込む場合は、他の題材にも適用すべきかを検討する。

AIは、見ていない資料を読んだことにしたり、未実装の操作を確認済みとしたりしない。制作上の提案、机上での点検、実機での確認、読者による試遊を区別して報告する。

共通仕様の有効性は、異なる題材や登場人物でも、C01〜C20の基準を使って制作・改稿できるかで見直す。特定のAIでだけ通じる表現や、特定作品にしか合わない必須条件が見つかった場合は修正する。

## 14．『さいごの、しろいページ』への適用例

この章だけは作品固有の適用例である。他作品へ人物・画面数・素材数をそのまま引き継がない。第8稿の物語を改稿する章ではなく、追加指示を受けた見せ方の整理とする。

### 14.1 基本の見せ方

- 第8稿のP01〜P51と分岐を基準にする。画面番号と物語の意味を保ち、実機で必要なら分割・統合を記録する。
- 生徒、ピピ、お月見の人間たちの人物画像は制作・表示の必須対象にしない。ふじたの顔も表示しない。
- 第8稿の【絵】に人物が描かれていても、後から示された「想像で埋める」方針を優先する。台詞と本文で必要な出来事を伝える。
- ロケット内部・秘密基地などを、必ず一枚の背景画として作らない。本文と本・にんじん・メーターなどで場面を成立させる。
- P43の人間たちの好意は、人物画を必須にせず、地の文で笑顔やお菓子を伝える。台本で制作指示だけに書かれている重要情報は、読者に届く短い本文への置換案として扱う。
- 重要な情報を画像から文章へ置き換える際は、追加する文を明示する。画像を省略したまま、理解に必要な情報まで消さない。

### 14.2 場面と素材・参加の対応

| 画面 | 中心になる表現 | 参加・選択の扱い |
| --- | --- | --- |
| P01〜P03 | 本文と海・森・虹の紙。机・椅子・ふじたを全部描く必要はない | 紙を拾う。個別タップとまとめて拾う操作を用意 |
| P04 | 白い紙面と一文 | 手動で進む |
| P05〜P09 | 本文、必要な箇所の海の挿し絵、メーター | 「うみ／おふろ」はどちらも反応して先へ進む |
| P10〜P13 | 本文、森の絵、触る対象の印や小物 | 葉・木の実・小川の音と視覚反応。探索しなくても進める |
| P14〜P20 | 本文、紙、雨粒。雨宿りの木の挿し絵は必要な箇所のみ | 紙を守る、雨の音を楽しむ、描くものを選ぶ |
| P21〜P27 | 虹の挿し絵、観音開き、詩、白紙、にんじん | 眺める時間を読者が決める。「ひろげる」でも開ける |
| P28〜P32 | 本文と月夜の挿し絵、詩、にんじん | お月見の出来事は文章で伝える。書く選択は置かない |
| P33〜P38 | 本文、本、にんじん、メーター | 生徒を助ける理由を会話で示し、ページめくりへつなぐ |
| P39〜P42 | 海・森・選んだ雨・虹の記録 | 一枚ずつ手動でめくる。速さを問わず、一人ぶんに届く |
| P43〜P48 | 本文、にんじん、最後の白紙、決まりの言葉 | 別れ、感謝、書けない余白を読む。新しい正誤選択を足さない |
| P49〜P51 | 本文、本、必要なら写真、最後の一文 | 写真は採否未確定。採用する場合も学校の手がかりを伝える小さな表示でよい |

海・森・雨宿りの木・虹・月夜の生成画像5点は挿し絵として使える候補であり、全画面に敷く背景ではない。海・森・虹は冒頭の紙と終盤の旅行記に再利用する。

既存素材では「開いた本」「にんじん」「ウサコ」が候補になるが、加工の要否を個別に扱う。「開いた本」には既に絵が入り、「にんじん」はかじられた形、「ウサコ」はメガホン付きである。正面の「ふじた」画像は本文へそのまま出さない。画像を使うために顔や新しい行動を物語へ追加しない。

### 14.3 この作品の選択と残る設計事項

- 「うみ／おふろ」は、選択直後にどちらも受け止め、後に名前を知る発見・訂正型。選び直しを強制しない。
- 雨のページ3種は表現・好み型。すべて先へ進み、後半に選択を反映する。
- プロトタイプのスイッチの再挑戦型は、本作のこの二つの選択へ追加しない。
- 紙を守ったあとに文字がにじむ出来事では、操作の失敗として表示しない。紙を守れたという反応と、雨による変化を区別する。
- 雨の選択「しょんぼりした帽子」は人物画がなくても小物で表現できる。「あまやどりの三人」は人物を描かない方針に合わせ、本文による説明などの表現方法を作品側で定める。選択肢そのものを無断で削除しない。
- 海の紙に雨を描き加える場面と、後半で海・雨を順にめくる場面の見せ方は、同じ見開きの異なる部分を見せる等の方法を作品側で定める。無傷の海ページを勝手に追加しない。
- 生徒の怖さ、ふじたが自分で残る判断、読者の手伝いが届いたことを区別する。感情を操作の成否で評価しない。
